# SEC EDGAR Filing Explorer — Initial Implementation Plan

## Approach

Build the application from the empty workspace in small vertical slices: establish the TypeScript React/Fastify foundation, isolate SEC EDGAR access behind the backend, expose the required APIs, then add the three user workflows and verify the critical data transformations.

## Milestones

1. **Establish the application foundation** ✅ done
   1. ✅ Create the minimal React + TypeScript frontend (`frontend/`, Vite) and Fastify + TypeScript backend (`backend/`) as npm workspaces in a monorepo, alongside a `shared/` package for cross-project types.
   2. ✅ Configure development and production scripts (`dev`, `build`, `start`/`preview`) and TypeScript settings for each workspace.
   3. ✅ Add route shells for the Home (`/`), Companies (`/companies`), Company Filings (`/companies/:ticker/filings`), and Summary (`/summary`) pages using `react-router-dom`.
   4. ✅ Define `Company`, `Filing`, pagination, and summary API types once in `shared/src/index.ts` (`@sec-edgar/shared`), consumed by both `backend` and `frontend`.
   5. ✅ Set up test (Vitest + React Testing Library on the frontend, Vitest on the backend), lint (oxlint / ESLint), and type-check workflows per workspace.
   6. ✅ Verified: both dev servers start and respond, the production builds succeed, all route shells render, and all tests/lint/typecheck pass.
2. **Integrate SEC EDGAR data** — ✅ done
   1. ✅ HTTP client (`backend/src/services/sec/http-client.ts`): wraps `fetch` with the required SEC `User-Agent` header (configurable via `SEC_USER_AGENT`), a generic `fetchSecJson<T>` helper, and a minimal non-OK response check.
   2. ✅ Ticker metadata fetching (`backend/src/services/sec/companies.ts`): `fetchCompanies()` fetches `company_tickers.json` and maps SEC's raw object shape into `Company[]` (ticker uppercased, CIK zero-padded to 10 digits).
   3. ✅ Submissions fetching (`backend/src/services/sec/submissions.ts`): `fetchSubmissionsColumnar(cik)` fetches the main submissions document and follows every referenced historical filing-history file (verified against the live `data.sec.gov` API), returning all raw columnar batches; each batch's arrays (`accessionNumber`, `filingDate`, `reportDate`, `form`, `primaryDocument`) must be validated for equal length as an invalid-response check, since the same index represents the same filing across all of them.
   4. ✅ Normalization (`backend/src/services/sec/filings.ts`): `normalizeFilings(cik, batches)` flattens the raw columnar batches into `Filing[]` using only the fields defined in the current `Filing` type (`accessionNumber`, `filingDate`, `reportDate`, `form`, `primaryDocument`, `link`), rejecting any batch whose arrays have mismatched lengths rather than defaulting or inferring missing values — no `coreType` mirroring or safe-default fallbacks.
   5. ✅ Filing URL construction (`backend/src/services/sec/filing-url.ts`): `buildFilingUrl(cik, accessionNumber, primaryDocument)` builds the canonical `sec.gov` document URL (CIK without leading zeros, accession number without dashes — verified live).
   6. ✅ Error handling in the HTTP client (`backend/src/services/sec/http-client.ts` and new `errors.ts`): `fetchSecJson` now enforces a request timeout (`SEC_REQUEST_TIMEOUT_MS`, default 10s) via `AbortController`, and throws specific `SecRequestError` subclasses instead of a generic `Error` — `SecTimeoutError`, `SecNetworkError` (fetch rejects before a response), `SecRateLimitError` (429, extends `SecHttpStatusError`), `SecHttpStatusError` (other non-OK statuses), and `SecMalformedResponseError` (non-JSON body).
   7. ✅ In-memory caching for ticker metadata and submissions responses.
   8. ✅ Remaining tests for the above (error paths, cache behavior).
3. **Deliver the backend API** — ✅ done
   1. ✅ Company discovery/search (`backend/src/handlers/companies.ts`, `backend/src/routes/companies.ts`, `backend/src/services/companies/search.ts`): `GET /companies` returns `Company[]` from `fetchCompanies()`, filtered by an optional case-insensitive `search` substring match against ticker/name, and paginated via `offset`/`limit` (Fastify querystring schema: `offset` default `0`; `limit` default `10`, max `100`).
   2. ✅ Ticker resolution (`backend/src/services/companies/lookup.ts`): `findCompanyByTicker(companies, ticker)` normalizes (trim + uppercase) and matches a ticker to its `Company`, returning `undefined` for an unknown ticker rather than throwing.
   3. ✅ Company filings retrieval (`backend/src/handlers/company-filings.ts`, `backend/src/routes/company-filings.ts`, `backend/src/services/filings/query.ts`): `GET /companies/:ticker/filings` resolves the ticker (404 if unknown), fetches/follows the company's full submissions history via `fetchSubmissionsColumnar` + `normalizeFilings`, then applies exact `form` filtering, `filingDate` sorting (`sort=asc|desc`, defaults to `desc`/most-recent-first), and `offset`/`limit` pagination (default `0`/`20`, max `limit` `100`), returning `PaginatedFilingsResponse`.
   4. ✅ Multi-company 12-month summary (`backend/src/handlers/filings-summary.ts`, `backend/src/routes/filings-summary.ts`, `backend/src/services/filings/summary.ts`): `GET /filings/summary?ticker=...` (repeatable) resolves each ticker, computes `filingsByForm` over a UTC trailing-12-month window (`twelveMonthCutoff`) and `latest10K` across the full history, and returns `SummaryResponse`. An unknown ticker or a per-company SEC failure is recorded in an `errors: SummaryError[]` array rather than failing the whole request (HTTP 200 with partial results).
   5. ✅ Shared API error handling (`backend/src/handlers/error-response.ts`): `sendErrorResponse` maps `SecRateLimitError`→429, `SecTimeoutError`→504, other `SecRequestError`→502, and anything else→500, without leaking internal error details; `describeErrorMessage` reuses the same classification to attach a per-ticker failure message in the summary endpoint's `errors` array instead of aborting the request.
   6. ✅ Tests for the above, co-located as `*.spec.ts`: pure-function coverage for search/filter/sort/pagination/summary-window logic, and Fastify `inject`-based route tests (success, filtering/sorting/pagination, unknown ticker/company, and each SEC error mapping) for all three endpoints.
4. **Deliver the browsing experience** — ✅ done
   1. ✅ Navigation: a shared layout/header component with links to Home, Companies, and Summary (`react-router-dom` `NavLink`), replacing the current route shells' placeholder content. Styled with Tailwind CSS.
   2. ✅ API data-access layer (`frontend/src/api/`): typed fetch functions for `GET /companies` and `GET /companies/:ticker/filings`, using the shared `@sec-edgar/shared` types, isolated from components.
   3. ✅ Company search (Companies page): a search input (debounced) driving the `search` query param, paginated results list/table, each linking to that company's filings page, via a custom `useCompanies` hook encapsulating fetching + pagination state.
   4. ✅ Filings table (Company Filings page, `frontend/src/hooks/useCompanyFilings.ts` + `frontend/src/pages/CompanyFilingsPage.tsx`): table of filings with columns for form, filing date, report date; controls for `form` filter (a `<select>` dropdown populated from the API's `availableForms` — the distinct form types actually filed by that company, computed server-side in `getAvailableForms` (`backend/src/services/filings/query.ts`) from the same full filing history already fetched per request, so the options are always accurate without extra round-trips), `sort` (asc/desc select), and pagination (offset/limit, with a page indicator via the shared `getPageInfo` helper); each row links out to the canonical SEC document URL (`link` field) in a new tab (`target="_blank" rel="noopener noreferrer"`). A `CompanySwitcher` combobox (`frontend/src/components/CompanySwitcher.tsx`, backed by a bounded/debounced `useCompanySearch` hook) on the filings page lets the user jump directly to another company's filings without returning to the Companies page; `useCompanyFilings` resets its filter/sort/pagination state whenever the route's ticker changes.
   5. ✅ Loading/empty/error states: both pages handle loading (`isLoading`), empty results, and errors explicitly; the filings page also distinguishes an unknown ticker (404 → "not found" message) from other API failures via the hook's `notFound` flag.
   6. ✅ Tests (`*.spec.tsx`/`*.spec.ts`): `useCompanyFilings.spec.ts`, `CompanyFilingsPage.spec.tsx`, `useCompanySearch.spec.ts`, and `CompanySwitcher.spec.tsx` cover the happy path, empty state, loading state, unknown-ticker/generic-error states, the form filter/sort controls, ticker-change state reset, and cross-company navigation via the switcher, using accessible queries (`getByRole`, `getByLabelText`).
5. **Deliver the comparison experience and quality checks** — ✅ done
   1. ✅ Summary API data-access (`frontend/src/api/summary.ts`): typed fetch function for `GET /filings/summary?ticker=...` (repeatable), consuming `SummaryResponse` from `@sec-edgar/shared`.
   2. ✅ Multi-select control (`frontend/src/components/CompanyMultiSelect.tsx`): a searchable combobox (reusing `useCompanySearch`) that adds companies to a selected list (chips, individually removable), guarding against duplicate selections.
   3. ✅ Comparison state (`frontend/src/hooks/useFilingsSummary.ts`): manages the selected-company list and an explicit "Compare" action that fetches `SummaryResponse` for the current selection, with loading/error/not-yet-compared/empty-selection states; surfaces per-ticker `SummaryError[]` alongside successful results rather than failing the whole view.
   4. ✅ Summary page (`frontend/src/pages/SummaryPage.tsx`): wires the multi-select, compare button, and a comparison table (per-company filing counts by form over the trailing 12 months plus latest `10-K` date), rendering the union of form types across selected companies as columns.
   5. ✅ Tests (`*.spec.ts`/`*.spec.tsx`): cover the multi-select's add/remove/duplicate-prevention behavior, the comparison hook's compare action and loading/error/empty states, and the Summary page's rendering of comparison results and per-ticker errors, using accessible queries.
   6. ✅ Quality gate: run `test`, `lint`, and `typecheck` across all workspaces (noting the known backend typecheck config caveat) to close out the milestone.
